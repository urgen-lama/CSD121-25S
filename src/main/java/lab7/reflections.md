The design of the searchRecipes function is able to  be used for testing using lambda expressions through dependency injection. The searchRecipes function is designed to take the data from the DataService interface as parameter. This approach decouples the searchRecipes function from a data source. The function only cares about the contract defined by DataService not the concrete implementation. This use of polymorphism is the reason the searchRecipes method can accept any object that implements the DataService interface. For testing, the mock test can be created easily using lambda expressions to provide list of recipes that are temporary. When (DataService) () -> List.of( ) is used it creates a temporary table in DataService object then when searchRecipes() calls getRecipes() on this mock object, the lambda code returns specific list of Recipe objects that can be test against. This helps to test searchRecipes in isolated way without depending on external sources like database. This way helps to create mock test for various scenarios.
